# RPGMVP to PNG — картинки RPG Maker MV (`*.rpgmvp`) → обычный PNG

Небольшая утилита на Python, которая снимает шифрование с картинок RPG Maker
MV (`*.rpgmvp`) и сохраняет их как обычные PNG. Зависимостей нет — только
стандартная библиотека Python 3.9+.

| Файл | Назначение |
|---|---|
| `rpgmvp2png.py` | сам конвертер: разбор `*.rpgmvp`, снятие XOR-шифрования, проверка PNG |
| `rpgmvp2png.bat` | «в один клик»: `input\` → `output\` (папку или файл можно перетащить на него мышью) |
| `verify.bat` | проверка без записи: расшифровать и сверить структуру PNG, ничего не создавая |

## Структура каталогов

```
RPGMVP to PNG/
  rpgmvp2png.py    конвертер *.rpgmvp -> PNG
  rpgmvp2png.bat   *.rpgmvp -> PNG «в один клик»
  verify.bat       проверка *.rpgmvp без записи
  README.md        эта документация
  input/           локальные образцы *.rpgmvp (не публикуются, лежит .gitkeep)
  output/          результат конвертации — PNG (не публикуется, лежит .gitkeep)
```

Оба каталога данных существуют в репозитории, но их содержимое в него не
попадает: `.gitkeep` сохраняет сами папки, а всё остальное исключено
корневым `.gitignore`.

## Быстрый старт

```bat
:: всё из input\ -> output\ (перезаписывая результаты)
rpgmvp2png.bat

:: свои каталоги
rpgmvp2png.bat "C:\game\img\pictures" "C:\game\img\png"

:: проверить, что все файлы целы, и ничего не писать
verify.bat
```

То же самое из командной строки:

```bat
python rpgmvp2png.py                              :: input\ -> output\
python rpgmvp2png.py "C:\game\img\pictures"       :: -> output\ рядом с pictures\
python rpgmvp2png.py "C:\game\img" --out png      :: свои каталоги
python rpgmvp2png.py "C:\game\img" --out png --flat --overwrite
python rpgmvp2png.py input --dry-run              :: проверка без записи
python rpgmvp2png.py input -v                     :: печатать каждый файл
```

Путь к каталогу можно не указывать: `rpgmvp2png.py` без аргументов берёт
`input\` рядом с собой и пишет в `output\`. Каталог обходится рекурсивно,
структура подкаталогов повторяется в результатах (ключ `--flat` складывает
все PNG в одну папку, совпадающие имена получают суффикс `_2`, `_3`, ...).

## Опции

| Опция | Описание |
|---|---|
| `ВХОД ...` | файлы `*.rpgmvp` или каталоги с ними; по умолчанию `input\` рядом со скриптом |
| `--out DIR` | каталог результатов; по умолчанию `output\` рядом с входным каталогом |
| `--flat` | не повторять структуру подкаталогов, все PNG в один каталог |
| `--overwrite` | перезаписывать существующие PNG (по умолчанию такие файлы пропускаются) |
| `--dry-run` | ничего не писать: расшифровать, проверить, напечатать сводку |
| `--no-check` | не сверять CRC чанков PNG (быстрее, но без проверки целостности) |
| `--key HEX` | ключ шифрования (32 hex-цифры) вместо автоопределения |
| `--system-json PATH` | взять ключ из поля `encryptionKey` файла `System.json` игры |
| `-v`, `--verbose` | печатать каждый файл |
| `-q`, `--quiet` | только ошибки |

Коды возврата: `0` — всё сконвертировано (или проверено); `1` — были ошибки
(список печатается после сводки); `2` — неверные аргументы.

## Формат `*.rpgmvp`

Файл — это обычный PNG, у которого **первые 16 байт зашифрованы**, а перед
ними стоит 16-байтовый служебный заголовок:

```
+0    16 байт   'RPGMV' 00 00 00 00 03 01 00 00 00 00 00   заголовок
+16   16 байт   первые 16 байт PNG, XOR с ключом игры
+32   ...       остаток PNG как есть (не шифруется)
```

Ключ — 16 байт, которые игра хранит в `data/System.json` в поле
`"encryptionKey"` (32 hex-цифры). XOR применяется только к первым 16 байтам
картинки; всё остальное тело файла не изменено, поэтому «расшифровка» — это
`(enc16 XOR key) + raw[32:]`.

### Почему ключ можно не указывать

Первые 16 байт любого PNG известны заранее:

```
89 50 4E 47 0D 0A 1A 0A   сигнатура PNG
00 00 00 0D               длина первого чанка (IHDR, 13 байт)
49 48 44 52               имя чанка 'IHDR'
```

Значит ключ восстанавливается из самого файла: `key = enc16 XOR plain16`.
Скрипт делает это автоматически и печатает найденный ключ при первом файле.
`--key` и `--system-json` нужны, только если файл повреждён (и восстановить
ключ из него нельзя) или если нужно свериться с конкретным ключом игры.

### Что проверяется после расшифровки

PNG разбирается по чанкам: сигнатура, `IHDR` первым чанком (длина 13),
отсутствие обрезанных чанков, завершение чанком `IEND` и — по умолчанию —
CRC каждого чанка через `zlib.crc32`. Байты после `IEND` ошибкой не считаются,
но учитываются в сводке. Неверный ключ сразу даёт `нет сигнатуры PNG`, а
повреждённое тело файла — `не сходится CRC чанка IDAT`.

Дополнительно скрипт понимает файлы, которые уже являются обычным PNG
(`encrypted=false` в игре): они копируются как есть, а в сводке попадают в
строку «уже были PNG».

## Ограничения

* Конвертация только в одну сторону: обратная упаковка PNG в `*.rpgmvp`
  не поддерживается.
* Ключ влияет только на первые 16 байт, поэтому «неверный ключ» не портит
  остальные данные — файл просто не пройдёт проверку сигнатуры.
* `*.rpgmvo` (звук) и `*.rpgmvm` (видео) этим инструментом не разбираются:
  у них та же схема шифрования, но другой набор расширений.
* Расширения `*.png` при конвертации не переименовываются в `*.rpgmvp`,
  а PNG, лежащие во входном каталоге, не обрабатываются — только `*.rpgmvp`.
