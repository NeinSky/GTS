# unrpa_3

`unrpa_3` — небольшой консольный распаковщик архивов Ren'Py (`.rpa` / `.rpi`), написанный на Python 3
(порт оригинального `unrpa` для Python 2). Скрипт читает оглавление архива, при необходимости снимает
XOR-обфускацию и извлекает файлы на диск, сохраняя структуру каталогов. Поддерживаются все три версии
формата: **RPA-1.0**, **RPA-2.0** и **RPA-3.0** (её использует современный Ren'Py, 6.3 и новее).

Зависимостей нет — только стандартная библиотека (`os`, `sys`, `optparse`, `pickle`, `zlib`).
Требуется Python 3 (проверено на 3.13).

## Состав проекта

| Файл | Назначение |
|------|------------|
| `unrpa_3` | сам скрипт (без расширения `.py`; запускается как `python unrpa_3 ...`) |
| `unpack.bat` | обёртка для Windows: `unpack.bat [архив.rpa] [каталог]` |

## Быстрый старт

```bat
:: распаковать archive.rpa в текущий каталог
python unrpa_3 archive.rpa

:: распаковать в свою папку, создав её при необходимости
python unrpa_3 -p "C:\games\mygame\extracted" -m game.rpa

:: только посмотреть содержимое, ничего не извлекая
python unrpa_3 -l game.rpa

:: подробный лог (по файлу на строку)
python unrpa_3 -vv -p out -m game.rpa

:: архив RPA-1.0, который не определяется автоматически
python unrpa_3 -f 1 old_archive.rpa
```

Windows-обёртка `unpack.bat` (лежит рядом со скриптом и архивом):

```bat
unpack.bat                     :: archive.rpa  ->  .\extracted
unpack.bat mygame.rpa          :: mygame.rpa    ->  .\extracted
unpack.bat mygame.rpa out      :: mygame.rpa    ->  .\out
```

## Опции

```
usage: unrpa_3 [options] pathname
```

| Опция | Описание |
|-------|----------|
| `-h`, `--help` | показать справку |
| `--version` | показать версию (1.1) |
| `-v`, `--verbose` | повысить подробность вывода; можно повторять: `-v` — уровень 2 (печатается каждый извлекаемый файл), `-vv` — уровень 3 (печатается создание каталогов) |
| `-s`, `--silent` | ничего не выводить (уровень 0) |
| `-l`, `--list` | только вывести список файлов архива (в отсортированном виде) |
| `-p PATH`, `--path=PATH` | каталог для распаковки (по умолчанию — текущий рабочий каталог) |
| `-m`, `--mkdir` | создать каталог из `-p`, если его нет (допустимо только вместе с `-p`) |
| `-f VERSION`, `--force=VERSION` | принудительно задать версию формата (`1`, `2` или `3`), если автоопределение не сработало |

Ограничения и проверки:

* ровно один позиционный аргумент — путь к архиву;
* `-p` нельзя использовать вместе с `-l`;
* `-m` работает только вместе с `-p`;
* `-l` нельзя комбинировать с `-s` (иначе нечего было бы выводить).

Коды возврата: `0` — успех; `1` — ошибка аргументов/формата; при неверном пути назначения
выводится `unrpa: error: path doesn't exist, if you want to create it, use -m.`.

## Автоопределение версии

* расширение `.rpa` — читается первая строка: `RPA-3.0 ` → версия 3, `RPA-2.0 ` → версия 2,
  иначе архив считается непонятным (`unrpa: error: file doesn't look like an archive, if you are sure it is, use -f.`);
* расширение `.rpi` — это всегда RPA-1.0;
* RPA-1.0 с расширением `.rpa` определяется только через `-f 1`.

## Кратко о формате RPA

Все версии — это конкатенация «шапки» (кроме 1.0), данных файлов и **оглавления** в конце архива.
Оглавление — это `pickle`-сериализованный словарь, сжатый `zlib`.

```python
index = {
    b"game/script.rpy": [(offset, length)],                 # RPA-1.0 / 2.0
    b"images/bg.png":   [(offset, length, prefix_bytes)],   # RPA-3.0, triplet
}
```

* ключ — путь внутри архива (в Python 2 это `str`/`bytes`; скрипт декодирует его как UTF-8 с `replace`
  и меняет `/` на `os.sep` текущей ОС);
* значение — **список** кортежей (на практике всегда один элемент, скрипт использует `data[0]`);
* `offset` — абсолютное смещение данных файла от начала архива;
* `length` — полная длина файла в байтах (включая `prefix`);
* `prefix` (только в RPA-3.0) — первые байты файла, хранящиеся прямо в оглавлении; в области данных
  лежат только `length - len(prefix)` байт, поэтому файл собирается как
  `prefix + f.read(length - len(prefix))`.

Оглавление в реальных архивах сериализовано Python 2 (pickle protocol 2), поэтому скрипт загружает
его с `encoding="bytes"` и дальше сам приводит ключи к `str` (UTF-8), а `prefix` — к `bytes`.
Список из `-l` печатается в отсортированном виде и с разделителями пути текущей ОС
(на Windows — `\`).

### RPA-3.0 (основной формат современного Ren'Py)

Первая строка — 34 байта:

```
RPA-3.0 <offset:16 hex-цифр> <key:8 hex-цифр>\n
```

* `offset` — смещение начала сжатого оглавления;
* `key` — 32-битный ключ обфускации; `offset` и `length` **каждой** записи оглавления хранятся как
  `значение ^ key` и восстанавливаются обратным XOR. Сами данные файлов не шифруются.

### RPA-2.0

```
RPA-2.0 <offset:16 hex-цифр>\n
```

25-байтовая шапка, оглавление лежит по смещению `offset`, обфускации нет, записи — пары `(offset, length)`.

### RPA-1.0 (`.rpi`, ранние версии Ren'Py)

Заголовка нет вовсе: файл целиком начинается со сжатого `zlib` оглавления, за которым идут данные.
Смещения в оглавлении абсолютные, обфускации нет.

### Пример разбора «на пальцах»

```
RPA-3.0 0000000000000100 1a2b3c4d
```
означает: оглавление начинается со 256-го байта файла, ключ `0x1A2B3C4D`. Запись оглавления
`(0x00000040 ^ key, 0x00000020 ^ key)` после снятия XOR даст файл длиной 32 байта со смещения 64,
то есть на диске нужно прочитать 32 байта начиная с 64-го и записать их как один файл.

## Замечания и ограничения

* Оглавление читается через `pickle`, поэтому **не запускайте скрипт на архивах из недоверенных
  источников**: подмена оглавления может привести к выполнению произвольного кода.
* Пустые каталоги из архива не воссоздаются — только каталоги, в которых есть файлы.
* Распаковка перезаписывает существующие файлы без предупреждения.
* Сжатие/упаковка архивов не поддерживается — утилита только извлекает.
* При ошибке в самом формате (например, `-f 3` для архива другой версии) скрипт может завершиться
  трассировкой Python — это ожидаемое поведение «принудительного» режима.
