# GME — ресурсы движка AGE: тома `*.ALF` и бандлы `*.acgf`

Небольшой набор утилит на Python, которые разбирают игровые архивы `*.ALF`,
достают из них ресурсы и конвертируют внутренние картинки движка в обычный PNG.

| Файл | Назначение |
|---|---|
| `alf_extract.py` | разбор томов `*.ALF`: находит и выгружает WAV/XWMA, шрифты, MPEG, контейнеры `SYS4472`, бандлы `*.acgf`; пишет манифест и отчёт о непокрытых областях |
| `acgf_tool.py` | разбор бандлов `*.acgf`: структура блоков, декод маски `ACIF` и цветного листа `page` в PNG |
| `acgf2png.bat` | «в один клик»: все `*.acgf` → PNG **с цветом и альфой** (RGBA) |
| `run_decode.bat` | то же, но только маски `ACIF` (8-битный серый PNG) |
| `run.bat` | «в один клик»: разложить все ресурсы из `etc\example\` в `etc\out\` |

Зависимостей нет — только стандартная библиотека Python 3.9+.

## Структура каталогов

```
GME/
  acgf_tool.py     разбор бандлов *.acgf
  alf_extract.py   разбор томов *.ALF
  acgf2png.bat     *.acgf -> PNG (цвет + альфа)
  run_decode.bat   *.acgf -> PNG (только маски ACIF)
  run.bat          тома *.ALF -> ресурсы
  README.md        эта документация
  etc/             локальные данные, в репозиторий не входят:
    acgf/          образцы *.acgf
    example/       тома DATA*.ALF
    out/           результат run.bat (манифест + извлечённое)
    png_rgba/      результат acgf2png.bat
    ...
```

Скрипты работают с любыми путями (аргумент командной строки), каталог `etc/`
— просто место по умолчанию для «входных/выходных» данных.

## Быстрый старт

```bat
:: 1. Достать ресурсы из тома (на выходе etc\out\<ТОМ>\acgf\*.acgf, wav, шрифты, ...)
python alf_extract.py "C:\game\DATA1.ALF" --out etc\out

:: 2. Сконвертировать бандлы в PNG с цветом и альфой
acgf2png.bat etc\out\DATA1\acgf etc\out\DATA1\png_rgba

:: 3. (необязательно) только маски ACIF — 8-битный серый
run_decode.bat
```

`acgf2png.bat` без аргументов берёт `etc\acgf\` рядом с собой и пишет в
`etc\png_rgba\`; папку или отдельный `*.acgf` можно просто перетащить на файл
мышью. На выходе — один PNG на картинку, имя = имя исходного `*.acgf`
(суффикс `_N`, если в файле несколько страниц). Внутри: цвет из листа `page`,
альфа из маски `ACIF`.

## Формат `*.ALF` (том)

Том — **плоская конкатенация объектов**. Ни заголовка тома, ни оглавления,
ни выравнивания нет: объект заканчивается ровно там, где начинается следующий.

Границы объектов восстанавливаются двумя способами.

**1. Самодостаточные форматы** — размер берётся из самого файла:

| Что | Признак | Размер |
|---|---|---|
| `RIFF`/`WAVE`, `XWMA` | `RIFF....WAVE` / `XWMA` | поле `RIFF size` |
| TrueType/OpenType/TTC | `00 01 00 00`, `OTTO`, `ttcf` | директория таблиц sfnt |
| PNG/JPEG/GIF/BMP/DDS | структура файла | по чанкам/маркерам |
| MPEG-1 program stream | `00 00 01 BA` | до маркера конца `00 00 01 B9` |

**2. Закрытые форматы движка** — длины нет, конец определяется по следующему
заголовку того же типа: `ACGF` (бандл картинок) и `SYS4472 ` (контейнер).

Внутри `SYS4472 ` лежат вложенные объекты (бандлы `*.acgf`, WAV/XWMA, шрифты),
поэтому извлечение рекурсивное, а в манифесте для каждой записи есть `depth`
и `parent`.

Так как в томах встречаются сжатые данные, все пробы проверяют инварианты
заголовков (маркеры, поля-счётчики) — иначе на гигабайт тома набираются
тысячи «картинок», из которых не открывается ни одна. Повторяющиеся объекты
по умолчанию схлопываются по SHA-1 (`--no-dedup` отключает).

## Формат `*.acgf` (бандл)

`*.acgf` — не картинка, а контейнер: последовательность блоков без оглавления,
у каждого свой заголовок, все поля — `u32` little-endian.

| Тег | Заголовок | Поля | Что это | Размер блока |
|---|---|---|---|---|
| `ACGF` | 24 байта | `ver=2, 0, 1080, 1080, N` | «лист» (страница) | до следующего заголовка |
| `00 00 00 00` | 24 байта | `ver=1, 0, 1080, 1080, N` | продолжение листа | до следующего заголовка |
| `ACIF` | 36 байт | `ver=2, 0, raw=w*h, w, h, raw, raw, comp` | 8-битная маска `w × h` | **точно**: `36 + comp` |
| `SYS4472 ` | 24 байта | `words[6]=0x1C`, `1≤words[3]≤64`, `words[5]≤64` | вложенный контейнер | до следующего заголовка |
| `RIFF` | 8 байт | `size`, `form` | вложенный WAV/XWMA | **точно**: `8 + size` |
| `xof 0303txt` | — | — | текстовая модель DirectX `.x` | до следующего заголовка |

`ACIF` — единственный блок с точной длиной; он служит точкой синхронизации
разбора (поэтому покрытие файла блоками получается 100 %).

### Лист `page`: где лежит цвет

Лист — это «BMP без магии `BM`» (в коде движка он называется **AGFBMP**):

```
+0     24 байта   заголовок листа ('ACGF', ver=2, 0, 1080, 1080, N)
+24   1080 байт   запись AGFBMP:
                   +0     2 байта    00 00 (на месте магии "BM")
                   +2    14 байт     префикс: u32 (полный размер), u32 0,
                                     u16 0, u32 pixoff = 1078
                   +16   40 байт     BITMAPINFOHEADER: w, h, planes=1,
                                     bpp = 8 / 24 / 32, imgsz = stride * h
                   +56 1024 байта    палитра: 256 записей BGRA
+1104  12 байт    дескриптор потока пикселей: raw, raw, comp
+1116  comp байт  LZSS-поток пикселей -> raw байт индексов (или BGR/BGRA)
```

* **палитра** — 256 записей **BGRA** сразу после `BITMAPINFOHEADER`; именно
  она даёт цвет (в большинстве файлов 8 бит на пиксель);
* **пиксели** — 8-битные индексы в палитру; строки лежат **снизу вверх** и
  выровнены по 4 байта (`stride = imgsz / h`), как в обычном BMP, поэтому
  перед выводом изображение переворачивается;
* встречаются 24- и 32-битные листы — там палитры нет, пиксели хранятся
  напрямую как BGR/BGRA;
* размеры берутся из самого листа (`BITMAPINFOHEADER`), а не из соседних
  блоков, поэтому лист декодируется независимо;
* в части файлов запись AGFBMP сжата тем же LZSS вместе с картинкой: тогда
  с `+24` идёт поток, первые 1080 байт которого — заголовок, а сразу за ним
  (после своего 12-байтного дескриптора) — поток пикселей. Оба варианта
  разбирает `decode_page_image()`.

Поле `N` в заголовке листа (149…1080) пока не объяснено; на разбор картинок
оно не влияет.

### `ACIF` — маска/альфа

* 1 байт на пиксель, `raw = w * h` (поле продублировано в заголовке трижды);
* значения `0…255`: `0` — фон, `255` — фигура, промежуточные — антиалиасинг,
  то есть это 8-битная **альфа/маска**, а не цветная картинка;
* размеры — любые (от 16 × 16 до ~1800 × 1900), обычно совпадают с размерами
  листа: `ACIF` — альфа того же изображения, что лежит в `page`.

### Кодек: LZSS 4096/18/3

Все сжатые потоки (`ACIF`, пиксели листа, сжатый заголовок AGFBMP) используют
один кодек движка:

* кольцевое окно 4096 байт, максимальная длина совпадения 18, порог 3,
  стартовая позиция записи `0xFEE`;
* флаги читаются байтом, биты — от младшего (LSB-first), признак «байт флагов
  уже прочитан» — установленный бит `0x100`; бит `1` — литерал, бит `0` —
  совпадение;
* совпадение — два байта: позиция `b0 | ((b1 & 0xF0) << 4)` — **абсолютная**
  позиция в кольцевом окне (не расстояние назад), длина `(b1 & 0x0F) + 3`;
* если в заголовке `comp == raw`, данные лежат без сжатия.

Декодер — `lzss_decompress()` в `acgf_tool.py` (~40 строк, без зависимостей).

## Инструмент `acgf_tool.py`

```bat
python acgf_tool.py --list <файл|папка>          :: структура блоков
python acgf_tool.py --check <файл|папка>         :: покрытие файла блоками
python acgf_tool.py --stats <файл|папка>         :: сводка: типы блоков, размеры ACIF
python acgf_tool.py --extract out <файл|папка>   :: вырезать нагрузки блоков как есть
python acgf_tool.py --extract png <файл|папка> --png-only --color --rgba   :: PNG (RGBA)
```

| Опция | Смысл |
|---|---|
| `--list` | показать блоки: тип, смещение, размер, поля заголовка |
| `--check` | проверить, что блоки покрывают файл без потерь |
| `--stats` | сводка по набору: типы блоков, размеры и степень сжатия `ACIF` |
| `--extract OUTDIR` | выгрузить полезные нагрузки блоков |
| `--csv FILE` | при `--list` дополнительно сохранить таблицу блоков в CSV |
| `--decode` | при `--extract` писать декодированные маски `ACIF` в PNG |
| `--png-only` | «плоский» режим: в каталоге только `.png`, без подпапок и служебных файлов |
| `--color` | брать цвет из листа `page` (палитра AGFBMP) вместо маски |
| `--rgba` | с `--color`: добавить альфу из `ACIF` (RGBA вместо RGB) |
| `--payload-png-width` | ширина «сырого» предпросмотра нагрузки (по умолчанию 256) |
| `--no-png` | не писать «сырые» PNG при обычном `--extract` |
| `--verify-decode` | метрика: сколько `ACIF` распаковывается ровно в `w*h` байт |
| `--verify-page` | метрика: сколько листов `page` разбирается в цветную картинку |

Поведение `--png-only`:

* один PNG на картинку, имя = имя `*.acgf` без расширения (плюс `_N` при
  нескольких страницах);
* по умолчанию — серая маска `ACIF`;
* `--color` — цветной PNG из листа, `--color --rgba` — цвет + альфа;
* если у листа нет `ACIF` того же размера, PNG пишется как RGB (без альфы);
  если лист вообще не разобрался, используется маска `ACIF`;
* каталог не очищается — для чистого результата указывайте новый путь.

## Инструмент `alf_extract.py`

```bat
python alf_extract.py --list <том|папка>          :: инвентаризация без записи
python alf_extract.py <том|папка> --out out       :: извлечь всё
python alf_extract.py <том> --out out --types wav,ttf
python alf_extract.py <том> --out out --no-blobs  :: только известные форматы
```

| Опция | Смысл |
|---|---|
| `--out DIR` | каталог результатов (по умолчанию `extracted`) |
| `--types SPEC` | `riff,wav,font,ttf,otf,ttc,jpeg,jpg,png,gif,bmp,dds,mpeg,mpg,acgf,sys4472,blob,all` |
| `--no-blobs` | не извлекать закрытые форматы движка (`ACGF`, `SYS4472`) |
| `--min-size N` | отбросить объекты меньше N байт |
| `--max-items N` | обработать только первые N объектов тома |
| `--list` | только показать найденное |
| `--top-level` | не разворачивать вложенные контейнеры |
| `--no-report-gaps` | не писать отчёт о неизвлечённых областях |
| `--primary-threshold P` | доля покрытия, при которой тип считается основным в томе |
| `--no-dedup` | сохранять дубликаты (по умолчанию одинаковые объекты схлопываются по SHA-1) |
| `--quiet` | не печатать каждую запись в режиме `--list` |

Результат:

```
etc\out\
  manifest.csv            манифест: volume;type;ext;offset;size;depth;parent;sha1;saved_as;meta
  DATA1_gaps.txt          области тома, не покрытые ни одной записью (offset, size, начало)
  DATA1\
    acgf\00001386C6_2e5b271e.acgf
    riff\000015A59E_b4545731.wav
    font\00000036E8_d6e9d66a.ttf
```

Имя файла — `смещение_в_томе` (10 hex-цифр) плюс первые 8 символов SHA-1,
поэтому повторные прогоны дают те же имена, а одинаковые объекты из разных
томов не перезаписывают друг друга. Колонка `meta` — короткий JSON
с параметрами объекта (размеры, формат, для контейнеров — поля заголовка).

## Примеры

Разложить все тома из каталога и сразу получить PNG для картинок:

```bat
python alf_extract.py "C:\game\*.ALF" --out etc\out
acgf2png.bat etc\out\DATA1\acgf etc\out\DATA1\png_rgba
```

Посмотреть структуру одного бандла и выгрузить только маску:

```bat
python acgf_tool.py --list etc\out\DATA1\acgf\00001386C6_2e5b271e.acgf
python acgf_tool.py --extract png etc\out\DATA1\acgf\00001386C6_2e5b271e.acgf --png-only
```

Извлечь из тома только звук и шрифты:

```bat
python alf_extract.py "C:\game\DATA1.ALF" --out etc\out --types wav,ttf
```

Убедиться, что разбор ничего не потерял:

```bat
python acgf_tool.py --check etc\out\DATA1\acgf
python acgf_tool.py --verify-decode etc\out\DATA1\acgf
python acgf_tool.py --verify-page etc\out\DATA1\acgf
```

## Надёжность разбора

Форматы закрытые, документации на них нет, поэтому разбор опирается не на
«угадывание», а на инварианты, каждый из которых проверяется самим
инструментом на ваших данных:

| Проверка | Что подтверждает |
|---|---|
| `--check` | блоки покрывают файл без потерь (нет «зазоров» и мусора) |
| `--verify-decode` | каждый `ACIF` распаковывается ровно в `w*h` байт |
| `--verify-page` | каждый лист собирается в картинку заявленного размера |

## Ограничения

* у `ACGF` и `SYS4472 ` нет поля длины: граница определяется по следующему
  заголовку того же типа, поэтому последняя запись цепочки «забирает» хвост
  до конца контейнера;
* блоки-продолжения листа (`00 00 00 00`) разбираются каждый сам по себе,
  а не склеиваются в одну страницу;
* поле `N` в заголовке листа пока не объяснено (на разбор не влияет);
* нулевой хвост пикселей в потоке не хранится — недостающие пиксели
  добиваются нулями (для прозрачных краёв это норма, но у обрезанных
  картинок видно как «недостачу»);
* если палитра листа пустая (все индексы = 255), цветной PNG получается
  однотонным — форма видна только по альфе из `ACIF`;
* если в бандле нет `ACIF` того же размера, что лист, PNG пишется как RGB
  без альфы (обычно это вторая страница файла).
